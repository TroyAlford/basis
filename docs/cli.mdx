# CLI

`basis/cli` is the `basis` command. It supplies repository tooling without requiring consumers to assemble the underlying ESLint, Stylelint, Markdown, TypeScript, or documentation stacks.

```bash
bunx basis lint
bunx basis format
bunx basis compliance
bunx basis emit
bunx basis typecheck
bunx basis doctor
bunx basis db plan
bunx basis db release
bunx basis db backup
bunx basis db restore <archive> [--image <image>]
bunx basis db upgrade <image>
bunx basis db rollback <archive> [--image <image>]
bunx basis docs check
bunx basis docs build
```

- `lint` reports the style policy and SQL diagnostics, and runs the typechecker. Warning-only diagnostics are actionable. It does not enforce paradigm or architecture rules.
- `format` applies every style autofix the policy supports and ignores warning-only diagnostics. SQL layout is applied by dprint.
- `compliance` runs `lint` plus the authoritative architecture and infrastructure rules and the typechecker. Pick either `lint` or `compliance` for a repository gate, not both.
- `emit` runs the conventional application emitter lifecycle; it is also run automatically before `typecheck`, `lint`, and `compliance`.
- `typecheck` runs Bun's built-in TypeScript checker; the checker requires Bun 1.4.3 or newer. The full Basis Server install requires Bun 1.4.6 or the approved canary described in [Installation](./installation.mdx).
- `doctor` verifies the installed consumer/runtime setup, including the Basis Server Bun requirement.
- `db` runs host database lifecycle operations against the managed installation. It resolves `graph.ts` and `migrations/` from the current directory; `graph.ts` may default-export the Graph or export it as `graph`. The application must be offline for `release`, `upgrade` and `rollback`; scheduling and retention remain host responsibilities.
- `docs check` validates a docs tree; `docs build` writes the static documentation site.

The CLI is a facade over the same code and policy exported through `basis/eslint`, `basis/stylelint`, `basis/markdown`, and `basis/tsconfig/*`. It does not replace repository-specific scripts or add a second configuration system. `basis check` is no longer supported; use `basis compliance`.
