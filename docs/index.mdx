# Why Basis

Basis exists to build working software that stays readable and maintainable after the first release. Correctness comes first; architecture, abstractions, type systems, tests, and tooling exist to serve correctness and comprehension, not to provide ceremony around it.

This repository is a deliberately cohesive system within its chosen scope. It is not designed to interoperate with every runtime, framework, or deployment model, and it does not treat extensibility as a default virtue. Where an outside capability is actually needed, it is added deliberately and owned; speculative adapters and configuration for every possible ecosystem are not part of the design.

The monorepo is one implementation of those judgments. The React component hierarchy, server, configuration, logging, OAuth, testing, review policy, and CLI share conventions, ownership, and a coordinated release because that lets the whole system stay coherent. Coherence is the point; universal compatibility is not.

The source is open so others may use all of Basis, one package, one component, or one idea; they may modify it or disagree with it. Using any part does not require adopting every Basis convention or enforcement policy. The [Engineering Principles](./engineering-principles.mdx) explain the reasoning in detail, and [Architecture](./architecture.mdx) describes how the integrated system is put together.
